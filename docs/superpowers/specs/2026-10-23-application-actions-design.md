# Помощник на шаге продукта и действия в списке заявок

Петя одобрил реализацию в чате 23.10.2026. Документ фиксирует согласованный объём, а не готовность кода. Дополнительных промежуточных подтверждений для этого объёма не требуется.

## Выбранный подход
- Плашка «Не уверены, что выбрать?» находится под вариантами продуктов только на втором шаге. Правую панель не меняем. Состояние раскрытия хранится у формы и переживает смену шага; новая заявка получает новое состояние. Модель не подключается.
- Карточка открывается по всей площади и с клавиатуры. Стрелка остаётся визуальной подсказкой. Удаление — отдельная соседняя кнопка, без вложенных кнопок и без открытия заявки.
- «Удалить черновик» показывается только для DRAFT. Перед действием — подтверждение с номером и предупреждением об отсутствии восстановления. Удаление физическое, только своей неотправленной заявки, с проверкой актуальной версии и статуса на сервере под блокировкой строки. Прямой запрос не должен обходить ограничение кнопки. Успех удаляет карточку и обновляет счётчик; ошибка сохраняет карточку и доступна повторная попытка.

## Альтернативы и границы
Глобальный помощник отклонён командой; его польза сосредоточена на выборе продукта. Для списка выбран большой элемент открытия вместо маленькой стрелки. Архив всех статусов оставлен за рамками; отправленные заявки не удаляются, история сохраняется. Для черновика выбран реальный DELETE вместо скрытия только в браузере или мягкого удаления. Это небольшое удобство списка, а не способ существенно сократить размер БД.

## Контракт и хранение
`DELETE /api/v1/applications/{id}?version=N`: 204; 401 без входа, 404 отсутствующая/чужая, 409 устаревшая версия или уже не DRAFT, 422 неверная версия. После удаления GET/PATCH/повторный DELETE дают 404. Чужие данные не раскрываются.

Запись заявки удаляется, но ключ первоначального POST остаётся как квитанция с `application_id = null`: повтор старого создания даёт 410 APPLICATION_DELETED и не воскрешает заявку. Для существующей PostgreSQL требуется идемпотентное снятие NOT NULL с application_creations.application_id при старте; остальные данные и ограничения сохраняются. Новая схема создаётся обычным create_all. Проверки и миграцию сначала выполняем на отдельной БД с суффиксом _tests.

При смене профиля перед удалением интерфейс перепроверяет компанию; сервер использует только cookie. Конкурирующий PATCH/DELETE сериализуются блокировкой строки и версией. Разрыв связи не означает успех; повторное открытие списка показывает фактическое состояние.

## Проверка
Регрессии: помощник отсутствует на первом/третьем/четвёртом шаге, под продуктами на втором и остаётся раскрыт при возврате; текст карточки открывает форму, клавиатура работает, удаление не открывает форму; отмена/ошибка/задержка; кнопки нет для не-DRAFT. PostgreSQL: удаление и квитанция, повтор POST, чужая компания, без входа, не-DRAFT, версия, гонка с PATCH, повторяемая миграция старой схемы. Полные наборы frontend/backend, сборка, живая проверка на своей синтетической записи без очистки рабочей БД.
