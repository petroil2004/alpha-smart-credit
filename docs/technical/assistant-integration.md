# Необязательный помощник: запуск и проверка

Основной кредитный сценарий работает без модели. Помощник доступен CLIENT в собственном DRAFT на шаге продукта: выбор продукта, сравнение условий, объяснение разрешённых банковских понятий. После подачи клиент общается с сотрудником в заявке.

## Модель и происхождение

Используем `qwen3:4b-instruct-2507-q4_K_M` из [Ollama](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M), открытые веса [Qwen/Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), лицензия Apache-2.0. Веса не входят в Git, скачиваются один раз; платная подписка не нужна. GPU необязателен. На CPU ожидание особенно первого ответа может быть заметным. Интернет нужен при скачивании, после загрузки возможно локальное использование.

## Основной вариант: Ollama отдельно, приложение в Docker

1. Установить Ollama с https://ollama.com/download на компьютер проверяющего.
2. Загрузить модель:

```bash
ollama pull qwen3:4b-instruct-2507-q4_K_M
ollama list
```

3. Для доступа из Docker сервер должен слушать интерфейс, доступный контейнеру. Закрыть уже работающую Ollama в трее/меню перед отдельным `serve`, чтобы не занять порт дважды. Windows PowerShell:

```powershell
$env:OLLAMA_HOST="0.0.0.0:11434"
$env:OLLAMA_CONTEXT_LENGTH="4096"
$env:OLLAMA_NUM_PARALLEL="1"
ollama serve
```

macOS/Linux:

```bash
OLLAMA_HOST=0.0.0.0:11434 OLLAMA_CONTEXT_LENGTH=4096 OLLAMA_NUM_PARALLEL=1 ollama serve
```

Слушающий на всех интерфейсах сервер нужно ограничить локальным компьютером/доверенной частной сетью через firewall. Не пробрасывать порт роутера и не открывать Ollama в интернет. На компьютере с уже запущенной службой вместо второго сервера настроить ту же службу и перезапустить её.

4. В существующем `.env` приложения задать:

```dotenv
ASSISTANT_ENABLED=true
LLM_BASE_URL=http://host.docker.internal:11434/v1
LLM_API_KEY=
LLM_MODEL=qwen3:4b-instruct-2507-q4_K_M
LLM_TIMEOUT_SECONDS=180
LLM_RESPONSE_FORMAT=json_schema
```

Для Docker Desktop на Windows/macOS используется `host.docker.internal`. Для Linux Docker Engine добавлен файл `compose.host-llm.yaml` с `host-gateway`:

```bash
docker compose -f compose.yaml -f compose.host-llm.yaml up -d --build --wait
```

Windows/macOS:

```bash
docker compose up -d --build --wait
```

При уже работающем приложении сохранять имя проекта (`-p`); после изменения `.env` достаточно пересоздать backend с прежними compose-файлами: `up -d --no-deps backend`. `.env` в Git не добавлять.

Если модель на другом компьютере доверенной сети, вместо `host.docker.internal` указать его частный IP. Компьютер автора и RTX3060 не требуются для независимой проверки.

## Дополнительный вариант: CPU-модель в Docker

В `.env` заменить `LLM_BASE_URL=http://ollama:11434/v1`, остальные LLM-настройки оставить. Запустить:

```bash
docker compose --profile assistant up -d --build --wait
docker compose --profile assistant exec ollama ollama pull qwen3:4b-instruct-2507-q4_K_M
```

Профиль ограничен 4 CPU (`OLLAMA_CPU_LIMIT`) и 6 ГиБ памяти; ресурсы приложения/БД нужны дополнительно. Ориентир — 12 ГБ RAM на компьютере и не менее 15 ГБ свободного диска. Это конфигурация, не гарантия производительности. На Mac GPU внутри Docker Desktop не предполагается. Веса сохраняются в отдельном volume `ollama_models`, заявки — в `postgres_data`. Порт Ollama не публикуется. Остановка без удаления: `docker compose --profile assistant stop`; повторный запуск: `docker compose --profile assistant up -d --wait`.

Историческое измерение CPU-прогона: [отчёт 25.10](2026-10-25-jury-cpu-verification.md); скорость зависит от компьютера, новые возможности нужно проверять текущим сценарием.

## Свой провайдер

Достаточно заменить `LLM_BASE_URL` (с `/v1`), `LLM_API_KEY`, `LLM_MODEL` и пересоздать backend. Модель должна иметь открытые веса; доступ к платному провайдеру не обязателен. Нужны `/models` и `/chat/completions`, не потоковый режим, JSON-ответ. Если провайдер не поддерживает strict JSON schema, задать `LLM_RESPONSE_FORMAT=json_object` или `none`; backend всё равно валидирует полученный JSON. Ключ остаётся только на сервере.

## Поведение и безопасность

Модель возвращает только `intent`, `product_code`, `topic` по закрытой схеме. Темы: overdraft, limit, payment, interest, preliminary, documents, stages, products. Серверный справочник `backend/app/assistant_knowledge.py`, версия `credit-glossary-v1`; числовые условия — `product_catalog.py`. Неподдерживаемые темы отклоняются. Ответ не содержит свободного текста модели. Ошибочная классификация всё ещё возможна, поэтому это не обещание безошибочности.

Нет инструментов, SQL, выполнения кода, изменения заявки и принятия решений. Backend не добавляет в запрос финансы, ИНН, документы или скоринг. Сообщения пользователя могут содержать введённый им текст; использовать только синтетические данные. История хранится в памяти интерфейса, не в БД.

GET `/api/v1/assistant/status`: доступность и допустимое время ожидания. POST `/api/v1/assistant/chat`: application_id, message, history. До 1200 символов на сообщение, до 6 сообщений истории, суммарно 4000; клиентская system-роль запрещена. Максимум один запрос на процесс, ответ провайдера ограничен 64 КиБ и 128 токенами, тайм-аут 1–300 секунд. Поздний ответ после ухода/смены аккаунта не применяется. Продукт выбирается только явной кнопкой клиента.

## Проверка

Открыть 8080 → клиент → черновик → «Помочь с выбором». Вопросы и ожидаемые результаты — [сценарии жюри](../jury/scenarios.md#помощник). Проверить как минимум выбор оборудования, объяснение овердрафта, лимита, постороннюю тему и запрет действий. Введённые параметры заявки не должны самопроизвольно меняться. При остановленной модели оформление вручную продолжается.
