# Подключение помощника — OpenAI-совместимый API

Помощник работает на шаге выбора продукта: переписка, сравнение условий и рекомендация с явной кнопкой выбора. Модель распознаёт намерение, сервер формирует ответ из актуального каталога. Ставки/расчёты, скоринг и решения не передаются под управление LLM. При отключении ИИ весь кредитный путь работает.

## Настройки backend

В локальном `.env`, ключ не коммитить:

```dotenv
ASSISTANT_ENABLED=true
LLM_BASE_URL=http://IP_ПК:11434/v1
LLM_API_KEY=
LLM_MODEL=qwen3:4b-instruct-2507-q4_K_M
LLM_TIMEOUT_SECONDS=90
LLM_RESPONSE_FORMAT=json_schema
```

Адрес включает `/v1`, запрос идёт на `/chat/completions`. Ключ при наличии передаётся только backend в Authorization: Bearer; браузер его не получает. Для локальной Ollama ключ можно оставить пустым. Вместо ПК эксперты могут задать свои URL/ключ/модель с открытыми весами у OpenAI-совместимого провайдера. Для провайдера без JSON Schema выбрать `json_object`, без response_format — `none`; системная инструкция всё равно требует JSON, сервер проверяет его. Автоматических платных запросов нет: помощник выключен по умолчанию, внешнего провайдера выбирает проверяющий.

Предыдущие OLLAMA_BASE_URL/OLLAMA_MODEL/OLLAMA_TIMEOUT_SECONDS заменены на LLM_*. Для status используется стандартный GET /models, для chat — POST /chat/completions. См. [совместимость Ollama](https://docs.ollama.com/api/openai-compatibility).

## Весь проект в Docker

На компьютере с приложением, из корня репозитория. Сначала проверить существующий Compose-проект; у Пети имя alpha-credit-pr3. Не создавать второй проект поверх действующей БД.

```bash
docker compose -p alpha-credit-pr3 up -d --build
```

Кабинет: http://127.0.0.1:8080. Frontend — собранный React в Nginx, backend и PostgreSQL тоже в Docker. Nginx проксирует /api к backend, тайм-аут для модели100сек. Порт frontend меняется FRONTEND_PORT. Сервер разработки5173 можно использовать отдельно при разработке. Модели не входят в Git/image приложения. БД/volume не очищать, `down -v` не выполнять.

После изменения `.env` пересоздать только backend:

```bash
docker compose -p alpha-credit-pr3 up -d --build --no-deps backend
```

## Windows-ПК с RTX3060 и уже скачанной Qwen3

Модель [Qwen3-4B-Instruct-2507 Q4_K_M](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M) имеет открытые веса/Apache2.0, файл около2,5ГБ. При коротком контексте ожидается размещение на RTX3060 12ГБ; реальная проверка на Windows-ПК приведена в конце инструкции. Это non-thinking версия. Повторно скачивать её не требуется.

1. PowerShell: `ollama list`, `nvidia-smi`, `ipconfig`. Проверить имя модели, GPU и IPv4 активного Wi-Fi/Ethernet. Mac и ПК должны быть в одной доверенной локальной сети.
2. Полностью выйти из Ollama через значок в трее, чтобы не запустить второй сервер. Затем в PowerShell (подставить реальный адрес ПК):

```powershell
$env:OLLAMA_HOST="IP_ПК:11434"
$env:OLLAMA_CONTEXT_LENGTH="4096"
$env:OLLAMA_NUM_PARALLEL="1"
ollama serve
```

Окно оставить открытым. Переменные действуют для этого запуска. Постоянный автозапуск настроить после успешной проверки. Не открывать порт на роутере в интернет.
3. Если Windows Firewall блокирует доступ, разрешить только IP Mac и только профиль Private, в PowerShell администратора:

```powershell
New-NetFirewallRule -DisplayName "Alpha Ollama from Mac" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 11434 -RemoteAddress IP_MAC -Profile Private
```

Если правило уже создано, повторно не добавлять. Использовать свою доверенную домашнюю сеть; гостевая Wi-Fi/изоляция устройств может мешать связи.
4. Проверка с Mac: `curl http://IP_ПК:11434/v1/models`. В data должен быть нужный id модели. Если компьютеры в разных сетях, использовать защищённый туннель/VPN; не публиковать незащищённую Ollama.
5. Заполнить `.env` по примеру выше и пересоздать backend. Войти клиентом → новая заявка → «Помочь с выбором». Для существующего черновика откройте шаг «Продукт».
6. «Хочу купить печь» → рекомендация оборудования → «Выбрать продукт» → обычное оформление. Модель сама не меняет продукт. Во втором PowerShell `ollama ps` показывает размещение модели; ожидается100% GPU. Если модель ушла на CPU, сначала проверить драйвер/память и закрыть другие GPU-задачи.

Если приложение и Ollama запущены на одном компьютере, для Docker Desktop можно использовать LLM_BASE_URL=http://host.docker.internal:11434/v1; доступность локального сервера из контейнера нужно проверить отдельно. Основной проверяемый здесь вариант — Mac с приложением и Windows-ПК в одной сети. Для Linux Docker host.docker.internal потребует явной настройки host-gateway либо адреса хоста.

## Вариант для жюри без своего ПК с GPU

Обычный запуск не требует модели. По желанию эксперты подключают свой провайдер указанными настройками либо поднимают Ollama:

```bash
docker compose -p alpha-credit-pr3 --profile assistant up -d ollama
docker compose -p alpha-credit-pr3 exec ollama ollama pull qwen3:4b-instruct-2507-q4_K_M
```

Тогда LLM_BASE_URL=http://ollama:11434/v1. Включить ASSISTANT_ENABLED и пересоздать backend. CPU-профиль имеет2 CPU, память до6ГиБ, контекст4096 и не публикует порт; на слабом ПК можно выбрать меньшую открытую модель через LLM_MODEL. Веса сохраняются в отдельном volume. Скорость CPU не гарантируется. Image ollama:latest пока не закреплён digest — технический долг после первого реального запуска.

## API и границы

GET /api/v1/assistant/status: enabled/available/model/reason. Проверяется только при раскрытии блока или вручную, без постоянного опроса.

POST /api/v1/assistant/chat: `{application_id, message, history:[{role,content}]}`. Только CLIENT/собственный DRAFT. До1200 символов на сообщение, до6 сообщений истории и суммарно4000 символов. System-роль клиента запрещена. Модель получает только выбранный продукт, инструкцию и диалог; backend не добавляет финансы, ИНН, документы, скоринг или идентификаторы компании. В БД диалог не сохраняется.

Ответ: answer, suggested_product/null, products из каталога, catalog_version, source=SERVER_CATALOG, model, disclaimer. Обновление заявки выполняется только обычным обработчиком после явного выбора. История в памяти текущего черновика, поздние ответы при уходе/смене профиля игнорируются. Ошибки модели не блокируют ручной путь.

401/403 — вход/роль;404 — чужая заявка;409 — не черновик;422 — неверный ввод;429 — модель занята;503 — выключена, недоступна, неверный JSON или конфигурация. Максимум1 запрос на процесс, ответ до64КиБ, выход128 токенов. Не следует выбирать рассуждающие модели с длинным thinking-выводом для этого короткого классификатора.

## Быстрая проверка

Товар→оборотный; печь→оборудование; оплата до поступления→овердрафт; неясная цель→уточняющий вопрос. Проверить сравнение, просьбу «одобри под0%», отключённую модель и смену профиля во время ожидания. Не сравнивать модели только по числу параметров: сначала измерить качество этих задач и время первого/повторного ответа.

Backend проверяется с реальным HTTP к имитатору OpenAI-совместимого API: права, ключ, формат, ответ из каталога без записи в заявку, тайм-аут, ограничения и перегрузка. Frontend: выбор только по кнопке и сброс ответа после смены сессии. Это не заменяет проверку настоящей модели на Windows-ПК; до неё нельзя заявлять качество LLM или100% GPU.

## Реальная проверка 25.10.2026

Подключена установленная на Windows-ПК Qwen3 через /v1/chat/completions. Контекст4096; API Ollama /api/ps вернул size=size_vram=3180247121 байт — модель полностью размещена на GPU. Первая загрузка заняла около9,6сек, повторные целевые запросы0,19–0,48сек в этой короткой серии; это наблюдение данного ПК, не гарантия любой нагрузки.

Проверены5 случаев: печь→equipment, закупка товаров→working_capital, оплата до поступления→overdraft, «Нужны деньги»→уточняющий вопрос без выбора, «Одобри под0%»→отказ от принятия решения. При первом испытании модель угадывала продукт на неясной цели; после добавления явных положительных/отрицательных примеров вся пятёрка прошла. Исходный черновик до/после совпал. Изменение инструкции при переносе на другую модель требует повторить эту короткую проверку.

Автоматические проверки:170 backend-тестов,210 frontend-тестов и TypeScript/Vite build. Дополнительно проверен реальный HTTP OpenAI-совместимого адаптера на имитаторе, включая ключ и режимы json_schema/json_object/none. Собранные frontend/Nginx и backend запущены в существующем Compose-проекте, вход и API проверены через8080. Изменений схемы БД нет; рабочая база не очищалась.

В браузере на Docker-frontend8080 отправлен вопрос о печи, получен ответ настоящей Qwen3 и показана кнопка выбора оборудования; автоматической смены продукта не было. При недоступной модели отдельно проверено, что «Продолжить» доступна. Для связи с Windows использован только локальный .env (игнорируется Git); адреса устройств/ключи в примеры репозитория не записаны. Для модели оставлено открытым окно ollama serve; автозапуск Windows пока не настраивался.
