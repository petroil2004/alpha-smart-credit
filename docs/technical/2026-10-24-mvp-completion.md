# Завершение связного MVP — 24.10.2026

## Что работает

Клиент проходит маршрут **продукт → параметры → проверка** для оборотного кредита, оборудования или овердрафта. Перед отправкой он видит профиль компании, шесть завершённых месяцев финансов, условия и расчёт. Сервер сохраняет неизменный снимок заявки, профиля, финансов и расчёта.

Сотрудник видит отправленную заявку в очереди и всю карточку. Он может запросить текст, документ и структурированные финансовые значения. Текст и вложение помечены как сведения клиента и сами не меняют расчёты. Только значения с месяцем, видом, суммой и источником `CLIENT_DOCUMENT` или `CLIENT_CONFIRMED`, которые явно принял сотрудник, участвуют в следующем расчёте; это фиксируется в заявке.

Серверный модуль `demo-scorecard-v0-temporary` прозрачно показывает балл 0–100, группу, причины, формальные проверки и недостающие сведения. Он использует возраст бизнеса, стабильность поступлений, операционный поток и текущую долговую нагрузку. Это временное воспроизводимое правило для хакатона, а не утверждённая банковская модель. Автоматическое решение не выносится: сотрудник вручную одобряет либо отклоняет заявку. Для отказа и решения по средней группе нужна причина; одобрение блокируется, пока оценка рекомендует запросить сведения или отказ.

ИНН, ОКВЭД и статус регистрации берутся из PostgreSQL из постоянных синтетических профилей с источником `FNS_MOCK`. Это имитация запроса ФНС, внешних обращений нет.

Целевые серверные тесты проверяют права клиента/сотрудника, неизменность снимка, пересчёт только после принятия структурированных финансовых значений, балл и финальные статусы.

## Ограничения и технический долг

- Веса `demo-scorecard-v0-temporary` надо заменить согласованной таблицей Саши до демонстрации как банковского решения.
- Нет реальной интеграции с ФНС, БКИ, ЭП, выдачей денег и Ollama; все данные и решения синтетические.
- Изменения схемы добавляются совместимыми `ALTER ... ADD COLUMN IF NOT EXISTS`; отдельные миграции и журнал версий для прототипа не делались.
- Овердрафт рассчитывается сервером при отправке; отдельного интерактивного предварительного расчёта в форме пока нет.

## Навигация, профиль и прозрачный скоринг

По запросу Пети данные компании удалены с обоих шагов оформления и из клиентской карточки отправленной заявки. Теперь название компании в шапке открывает отдельный профиль с шестью месяцами финансов. Сотрудник сохраняет доступ к снимку при отправке. Логотип/название кабинета возвращают на главную через прежнее сохранение; карточки продуктов создают заявку с нужным продуктом. Отступы «Назад» и «Сохранить и выйти» выровнены:26px с обеих сторон.

Прежняя временная формула скоринга теперь явно считает коэффициент × вес25 для возраста, стабильности поступлений, операционного потока и долговой нагрузки. Итоговые баллы/пороги сохранены. API возвращает criteria с исходным показателем, коэффициентом, весом и вкладом; сотрудник видит таблицу. Имитация ФНС/действующая регистрация и доступность платежа проверяются отдельно. Ассистент не дорабатывался.

Проверки:166 backend-тестов,208 frontend-тестов, TypeScript/Vite build. Добавлены только3 проверки выбора продукта; прежние тесты профиля адаптированы к отдельной странице, серверный тест проверяет сумму вкладов. В браузере проверены отдельный профиль, возврат логотипом, создание оборудования с выбранным продуктом и отсутствие финансов на проверке. У кнопок визуально и по computed style подтверждены симметричные отступы. Для проверки оставлен новый черновик оборудования CLIENT4 `93ad2d6f-9de6-40f5-ae32-da6253b0eee0`; прежние пользовательские черновики не изменялись.
