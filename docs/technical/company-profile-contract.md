# Профиль и финансы демо-компании — контракт

[Спецификация](../superpowers/specs/2026-10-24-demo-profiles-design.md), [план](../superpowers/plans/2026-10-24-demo-profiles.md). Реализован в codex/petya-demo-profiles, проверен на отдельной тестовой БД и действующем сервере; итоговая рецензия и исправления записаны в [отчёте](2026-10-24-demo-profiles-verification.md).

Авторизованный CLIENT читает свою компанию через прежний `GET /api/v1/company-profile`. STAFF получает403; без входа401. Идентификатор компании из пользовательского запроса не принимается. Внешних источников и регистрации аккаунтов нет.

Сохраняются company_id/company_name/source/profile_version. Новые поля:
- details: legal_form OOO/IP/null, tax_id и okved null в начальных наборах, registration_date YYYY-MM-DD|null, business_age_months integer|null, registration_status ACTIVE/TERMINATED/null, is_bank_client boolean|null.
- as_of_date: дата чтения по Europe/Moscow; prepared_on: дата первоначальной подготовки набора|null; data_version: версия набора|null.
- finance.period: start_date/end_date, шесть завершённых календарных месяцев.
- finance.months: ровно шесть хронологических строк {month:YYYY-MM,income_rub,expenses_rub,income_source,expenses_source}; деньги — строки с двумя знаками или null, источники BANK_DATA/null (сохранённый источник передаётся явно).
- finance.debt_payment_rub, debt_source, debt_as_of: месячные долговые платежи и источник/дата сведений, каждый nullable.
- finance.average_income_rub / average_expenses_rub: среднее только полного соответствующего ряда из6 значений, ROUND_HALF_UP до копеек; иначе null. Подтверждённый ноль учитывается. Риск/доступность не рассчитываются.

profile_version — SHA256 полного показанного DTO без самого profile_version, префикс company-v2:. Период, дата, пропуски, источники и метаданные входят в подтверждение. Новая отправка фиксирует DTO; исторические версии снимка без этих полей допустимы и не дополняются актуальным профилем.

CompanyData и CompanyMonth создаются дополнительно к старой схеме без очистки. Seed под транзакционной advisory-блокировкой вставляет отсутствующие аккаунты/полные наборы из app/demo_data/company-profiles.json. Повтор не обновляет строки или даты. Несовпадающий аккаунт диагностируется и пропускается. Неполный существующий набор автоматически не ремонтируется. Новый календарный месяц без строки БД возвращается с null, без генерации и переноса прежних сумм.

Актуальный ответ API проверяется frontend целиком: обязательные nullable-поля, типы, шесть месяцев строго по as_of_date, календарные границы и отсутствие среднего для неполного ряда. Ошибка блокирует подтверждение и предлагает повтор загрузки. Исторические снимки не проходят live-валидатор и сохраняют прежнюю структуру.

## Финансовый пульс — 25.10.2026

GET `/api/v1/company-profile` дополнительно возвращает `financial_pulse`: состояние READY / INSUFFICIENT_DATA, score, level (GREEN/YELLOW/RED), metrics, series и missing. Расчёт выполняется сервером по данным той же компании; дополнительных таблиц и вымышленных остатков нет. При неполных поступлениях, расходах или неизвестном текущем долговом платеже балл и график не строятся. Частичные значения не заменяются нулями.

Пульс `financial-pulse-v2` использует плавную демонстрационную шкалу, отдельную от кредитного скоринга. При `v = (максимальные − минимальные поступления) / средние поступления`, `m = max(0, min(1, операционный поток / поступления))` и `d = долг / положительный операционный поток` балл равен `35 / (1 + v) + 40 × m^(1/3) + 25 / (1 + d)`. При нулевых поступлениях вклад стабильности равен нулю; без положительного потока вклад долговой нагрузки тоже нулевой. Округление HALF_UP до целого, максимум 99. Идеальные 100 потребовали бы одновременно постоянных поступлений, отсутствия операционных расходов и долгов. Хорошие показатели дают около 80–85. От 80 — GREEN, от 50 — YELLOW, ниже — RED. Это временные параметры демонстрационной сводки, не политика Альфа-Банка. Возраст бизнеса и параметры заявки не участвуют. Кредитный скоринг и правила принятия решения не изменены.

Показатели: средние поступления; доля `(поступления − операционные расходы) / поступления`; действующий долг / положительный операционный поток; свободный поток после операционных расходов и долгов. Изменение поступлений сравнивает средние последних трёх и первых трёх месяцев. При нулевой базе изменение не вычисляется; при неположительном потоке процент долговой нагрузки не показывается.

Это вычисляемая сводка для профиля, не отдельная сохранённая банковская оценка и не решение о выдаче. Поле не входит в исходные сведения, сохраняемые при отправке заявки, и не меняет profile_version — эта версия по-прежнему зависит от исходных данных компании. Иллюстрация в шапке — предоставленный владельцем PNG, без изменения содержимого.

## Подтверждённые исправления сотрудника

При сохранении ручной корректировки через `financial-corrections` или `profile-corrections` изменённые поля также записываются в `CompanyData` / `CompanyMonth` этой компании в одной транзакции с историей исправления и пересчётом заявки. Обновляются только переданные поля; неизвестные значения не заменяются нулями. Отсутствующие месячные строки создаются по явно указанному месяцу. Источник — STAFF_VERIFIED, версия набора меняется. Повтор с тем же ключом операции не применяет корректировку заново.

После открытия или обновления профиля клиент видит актуальные подтверждённые данные и новый пульс; они также используются для новых заявок. Старые месяцы сохраняются по своей дате и не переносятся в текущий период. Первоначальные сведения ранее отправленных заявок сохраняются отдельно; корректировка одной заявки не переписывает исходные сведения и расчёты других уже отправленных заявок. Ранее записанные до этого изменения корректировки автоматически не переносятся в общий профиль.
