# Единый чат уточнений — 25.10.2026

Эта версия заменяет прежнюю схему «ответ отдельно, чат отдельно» из `clarifications-contract.md`.

- Сотрудник создаёт запрос одним текстом `question`; `reason` необязателен и сохраняется для старых записей. Можно отметить обязательный документ. Без этой отметки загрузка файлов недоступна и в интерфейсе, и в API. Отдельной клиентской анкеты финансов нет.
- `PATCH /applications/{id}/info-requests/{rid}/reply` сохраняет личный черновик. PUT вложения загружает личный файл. Оба доступны клиенту, сотруднику их текст/метаданные/байты не передаются. В истории скрыты события сохранения черновика и загрузки/открепления.
- `POST .../reply/submit` с `{version,revision}` атомарно создаёт сообщение клиента и связывает с ним ещё не отправленные вложения. Текст черновика очищается, `reply_submitted_at` фиксируется, статус остаётся NEEDS_INFO. Можно отправить один документ без текста. Повтор с прежним Idempotency-Key не дублирует сообщение.
- `POST /staff/applications/{id}/info-requests/{rid}/messages` отправляет текст сотрудника. Обе стороны могут общаться, пока запрос открыт. Просто набранный текст сотрудника остаётся в браузере. Клиент использует тот же единый композер для ответов и вопросов.
- `POST /staff/applications/{id}/info-requests/{rid}/close` с `{version,revision}` закрывает запрос и переводит заявку в UNDER_REVIEW. Требуется отправленный ответ клиента; при отметке документа нужен отправленный файл. Только STAFF. После закрытия новые сообщения/изменения отклоняются; идемпотентные повторы выполненных операций возвращают текущее состояние.
- Файлы: PDF, PNG, JPG/JPEG до 5 МБ (5 000 000 байт), пять активных вложений на запрос. Проверяются имя, расширение, MIME и сигнатура. Отправленный документ нельзя открепить. Старые TXT не удаляются, но новые не принимаются.
- `POST .../financial-corrections` доступен STAFF после отправленного ответа, при NEEDS_INFO или UNDER_REVIEW. Таблица начинается с исходных значений и накладывает принятые исторические поправки по времени. Сохраняются изменённые ячейки с основанием и автором; исходные сведения отправленной заявки не меняются, скоринг пересчитывается. Подтверждённые изменения также записываются в общие финансовые данные компании и доступны в профиле. Клиентские `financial_values` при отправке больше не принимаются. Старые принятые значения продолжают участвовать в исторических заявках.
- `POST .../profile-corrections` с `{version,reason,details}` доступен сотруднику после ответа клиента, до итогового решения. Изменения ИНН, формы, ОКВЭД, даты/статуса регистрации и признака клиента банка сохраняются в `staff_profile_corrections` с автором/временем. Возраст бизнеса пересчитывается на дату сведений заявки. Проверяются длина ИНН по форме, формат ОКВЭД и дата регистрации. `verified_company` содержит эффективные проверенные данные этой заявки; исходные сведения заявки сохранены отдельно, подтверждённые изменения также обновляют соответствующие поля общего профиля компании. Скоринг использует эти поправки.
- При пустом финансовом снимке шесть месяцев восстанавливаются по зафиксированному периоду или дате подачи, суммы остаются неизвестными до явного ввода сотрудника. Клиентские слова не заменяют числа автоматически.
- Аддитивное обновление БД добавляет дату отправленного ответа и ссылку вложения на сообщение. Старые закрытые запросы без новой даты остаются читаемыми как архив. Приватные файлы нового запроса не становятся видимыми при его закрытии.

Список заявок упорядочен по `updated_at` по убыванию. Сохранение черновика, сообщения, загрузка/открепление документов и поправки обновляют дату активности; в обеих ролях показано «Изм.» с датой и временем Москвы. Дни использования овердрафта вычисляются по датам клиентом и сервером; ручного ввода дней нет. Дата не может быть раньше текущего дня Москвы, в интерфейсе год ограничен четырьмя цифрами.


Актуализация 25.10.2026: поле стоимости оборудования и соответствующая проверка убраны из нового оформления; прежние значения в снимках сохранены. Сумма, срок и цель остаются обязательными. Овердрафт: сумма использования ≤ лимита, даты строго по порядку, срок 1–60 дней вычисляется по разнице дат, поступление покрывает использование и проценты. Условия проверяются на сервере; интерфейс показывает ошибки до отправки.
