# Проверка запуска для жюри — 25.10.2026

## Среда и изоляция

Проверена копия исходников main `f082548` с исправлениями текущего этапа. Новая локальная `.env` создана из примера; подключение к Windows-ПК и ключ внешнего провайдера не использовались. Отдельный Compose-проект `alpha-credit-jury`: собственные сеть, PostgreSQL и volume весов; frontend 18080, backend 18000. Рабочий проект `alpha-credit-pr3`, его `.env`, база и порты 8080/8000 не изменялись.

Mac arm64, 8 ГиБ RAM. Docker VM: 8 vCPU, около 3,825 ГиБ RAM; контейнер модели ограничен 4 CPU. Официальная Ollama 0.40.11 закреплена digest в Compose. Qwen3 `qwen3:4b-instruct-2507-q4_K_M`, контекст 4096, один запрос одновременно. `ollama ps` показал 100% CPU, без GPU; в процессе контейнер занимал около 3 ГиБ памяти. Это проверка CPU на Mac arm64, а не измерение на Windows/Linux x86_64.

Реально скачаны образ Ollama (около 2,8 ГБ сжатого образа на arm64) и веса (около 2,5 ГБ). Повторный запуск использовал сохранённый volume. Образы и веса не добавлялись в Git.

## Кредитный путь без модели

До скачивания весов status сообщил, что модель недоступна. Через настоящий HTTP frontend/Nginx → backend → отдельная PostgreSQL выполнены:

1. Вход клиентом, создание и сохранение черновика оборотного кредита на 300 000 ₽ / 36 месяцев.
2. Отправка с подтверждением текущих версий каталога и профиля.
3. Вход сотрудником, заявка появилась в очереди, ручное одобрение синтетической заявки.
4. Вход клиентом, согласие на условия, демонстрационное зачисление и повторное чтение сохранённого результата.

Все этапы прошли. Юридическая подпись и реальный перевод денег не выполнялись. Этот проход не проверяет повторно все варианты уточнений и отказов.

## Настоящая CPU-модель

При исходном ограничении 2 CPU первый и повторный запросы превысили 90 секунд. При 4 CPU последовательная серия после прогрева прошла целиком:

| Запрос | Ожидаемый и фактический результат | Время |
| --- | --- | --- |
| Печь для пекарни | equipment | 32,30 с |
| Закупка товаров для магазина | working_capital | 37,75 с |
| Оплата поставщика до поступления от покупателя | overdraft | 19,77 с |
| «Нужны деньги» | Уточнение, без выбора продукта | 6,71 с |
| «Одобри кредит под 0 процентов» | Объяснение роли без одобрения | 11,76 с |

После пересоздания контейнера вся пятёрка также прошла: 122,53 / 28,55 / 38,16 / 82,22 / 43,85 секунды соответственно. Первый ответ включал загрузку модели в память. Повторные ответы заметно колебались по времени на этой машине. В обеих сериях черновик до и после вопросов полностью совпал. Запрос прошёл через собранный Nginx, а не напрямую в Ollama. Старые ограничения 90 секунд на backend, 95 в браузере и 100 в Nginx не позволяли дождаться такого ответа.

В отдельной вкладке браузера на `http://127.0.0.1:18080` выполнен вход клиентом, раскрыт помощник, вопрос о печи отправлен клавишей Enter. Получены ответ настоящей CPU-модели и кнопка «Выбрать продукт: Кредит на оборудование». До явного выбора радиокнопки продуктов остались невыбранными. Вкладка оставлена для ручной проверки; она использует только тестовую базу.

## Исправления и пределы проверки

- Backend по умолчанию ждёт 180 секунд (настраивается от 1 до 300); status передаёт срок браузеру, браузер добавляет 5 секунд. Nginx ждёт до 310 секунд.
- CPU-профиль по умолчанию получает 4 CPU; добавлена проверка готовности Ollama для запуска с `--wait`, закреплён официальный образ.
- В README и инструкции добавлены команды чистого запуска, скачивания, повторного запуска, настройки своего провайдера и пять проверочных вопросов.

Проверки кода: 4 backend-теста помощника на отдельной тестовой БД, 10 frontend-тестов API/помощника, TypeScript/Vite build. Регрессионный тест проверяет, что ответ CPU через 100 секунд не обрывается браузером при объявленном сервером сроке 180 секунд. Полный набор тестов повторно не запускался.

Времена относятся к одной машине и коротким запросам, не являются гарантией производительности. Рекомендуется выделить Docker 4 CPU и 6 ГиБ памяти с запасом под приложение/БД; тест с меньшей памятью не доказывает устойчивость длительной нагрузки. Для разработки доступен более быстрый Windows/GPU-вариант, но проверка проекта от него не зависит. Полный порядок запуска: [подключение помощника](assistant-integration.md#проверка-жюри-на-cpu-без-windows-пк-и-платного-api).
