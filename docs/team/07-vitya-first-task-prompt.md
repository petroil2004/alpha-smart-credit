Ты работаешь с Виктором в команде хакатона. В этом GitHub-репозитории уже есть согласованные инструкции. Сначала прочитай AGENTS.md, README.md, docs/team/00-start-here.md, docs/team/02-vitya.md, docs/team/06-git-workflow.md и docs/superpowers/specs/2026-10-21-credit-cabinet-design.md. Наши персональные задания и ограничения находятся там; не начинай новый проект с нуля в другом репозитории.

Петя параллельно делает только frontend в своей копии и ветке codex/petya-client-draft. Ты делаешь backend, хранение и запуск в отдельной ветке codex/vitya-application-api от актуальной main. Проверь git status и remote; сохрани чужие изменения. Общие main и историю не переписывай.

Перед кодом получи общий контракт: git fetch origin, затем прочитай файл из ветки Пети командой git show origin/codex/petya-client-draft:docs/technical/api-contract.md. Не переключайся на ветку Пети и не сливай его незавершённую работу в свою. Если ветка или файл пока недоступны, попроси Виктора получить контракт от Пети, не придумывай другой API. При дальнейшем расхождении согласуй изменение контракта через Виктора и Петю до реализации.

Первая задача — работающий backend для демонстрационного входа и черновиков по этому контракту. FastAPI + PostgreSQL. Прочитай все поля, статусы, cookie-сессию, ошибки, версию для защиты от перезаписи и Idempotency-Key для повторного создания. Нужны два клиента из разных компаний, собственные списки, создание, получение и изменение черновика. Временные и неполные черновики допустимы; бизнес-пороги и ставки не придумывай. Финансовые значения храни точно, а не приблизительными дробями.

Твои файлы: backend/, backend/README.md, compose.yaml и .env.example для backend/БД. Не создавай frontend/, корневой package.json и параллельный контракт API; корневые README и AGENTS ведёт Петя. Не публикуй реальные секреты и не настраивай удалённый доступ к компьютеру Пети.

Работай небольшими шагами через проверки: сначала ожидаемое поведение, затем реализация. Проверь сохранение после перезапуска, изоляцию двух клиентов, 404 для чужой заявки, повтор создания с тем же ключом, конфликт version и проверку несовместимых полей. Сессия тоже должна переживать перезапуск при сохранённых БД и настройках. Не называй проверку SQLite доказательством совместимости с PostgreSQL. Добавь воспроизводимый запуск и проверки для настоящей PostgreSQL.

Сначала покажи Виктору короткий план и вопросы, которые действительно блокируют работу. После подтверждения реализуй этот шаг. Не делай сейчас скоринг, решения, выдачу, банковский интерфейс и полноценное подключение ассистента. Ollama — отдельная небольшая проверка, если останется время, и отдельная задача, без задержки черновиков.

В конце сообщи: как запустить, какие проверки действительно выполнены, что ещё не проверено, точные адреса и ожидаемые ответы для Пети. Когда Виктор поручит отправку, сделай осмысленные коммиты, push своей ветки и PR в main. Свою работу не объединяй без проверки другим участником. Пиши объяснения по-русски простыми словами.
