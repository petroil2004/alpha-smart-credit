# Первый интерфейс кредитного кабинета

## Три шага и утверждённое оформление

Маршрут: **Продукт → Параметры → Проверка**. Новый и повторно открытый черновик начинаются с выбора продукта. Отдельного шага «Потребность» и готовых карточек целей больше нет.

На первом шаге под тремя продуктами расположен раскрывающийся помощник. На параметрах и проверке его нет; раскрытие сохраняется при возврате. Это пока только интерфейс: модель не подключена, ввод и отправка отключены, запросов к LLM нет. Цель и сумма до выбора продукта не требуются; будущий помощник уточняет их в разговоре при необходимости.

На «Параметрах» под расчётами находится обычное поле «На что нужны средства» до 500 символов. Оно сохраняется как `purpose` прежним API. Старые произвольные цели и прежние готовые фразы остаются исходным текстом; при открытии/смене продукта не заменяются. Для неполного DRAFT описание необязательно. Отдельная структурированная категория исключена из обязательного MVP.

У кабинета тёмная общая шапка и приветственный блок на главной; список заявок светлый, со стандартным значком документа. Продукты используют пастельные карточки с локальными иллюстрациями; калькулятор — отдельный блок результата; сводка — простые строки. Правая панель пути заявки на узком экране переносится вниз. [Согласованный дизайн](../docs/superpowers/specs/2026-10-23-three-step-redesign.md).

## Калькулятор обычных кредитов

На шаге «Параметры» оборотного кредита и оборудования доступны ручной ввод и ползунки суммы/срока. Через 300 мс после изменения корректных параметров отправляется серверный расчёт; сводка показывает тот же актуальный результат. Ставки и пределы приходят из GET /api/v1/products, итог — из POST /api/v1/calculations/annuity. Формулы в браузере не дублируются.

Неполные значения и суммы вне каталога можно сохранить в черновике; подсказки калькулятора этого не запрещают. Ошибка загрузки условий оставляет ручной ввод, ошибка расчёта скрывает прежние суммы и позволяет повторить запрос. Сам запрос расчёта не изменяет заявку; ввод сохраняется отдельным механизмом автосохранения. Поздние ответы не заменяют результат новых параметров. Ручной ввод сохраняет копейки независимо от шага ползунка.

Калькулятор овердрафта, скоринг, финансовая оценка и отправка не входят в этот этап. Полный формат — в [контракте](../docs/technical/loan-calculator-contract.md). Для проверки живого калькулятора нужен backend из той же версии репозитория; старый сервер без новых методов оставляет только ручные поля и сохранение.

React + TypeScript + Vite. Реализован клиентский черновик: демонстрационный вход, список, пошаговое оформление, сохранение и повторное открытие. Backend и PostgreSQL уже есть в общей версии репозитория; без запущенного backend приложение показывает ошибку подключения, а не скрытое сохранение в браузере.

## Запуск

Нужен Node.js 22.12 или новее поддерживаемой ветки; разработка проверяется на 22.20.0. Все пакеты фиксируются в `package-lock.json`.

Из корня репозитория:

```bash
cd frontend
npm ci
npm run dev
```

Открыть адрес, показанный Vite, по умолчанию `http://127.0.0.1:5173`. Backend должен работать на `http://127.0.0.1:8000` и выполнять [общий API-контракт](../docs/technical/api-contract.md). Используйте один hostname в браузере и настройке разработки: по умолчанию 127.0.0.1.

Если backend по другому адресу, создать локальный `frontend/.env.local` с `VITE_API_PROXY_TARGET=http://127.0.0.1:8000`, заменив адрес. Перезапустить Vite. Этот файл не коммитится; никаких токенов или ключей в переменные VITE не помещать, они могут быть доступны браузеру. Запросы идут к `/api/v1` того же сайта, Vite перенаправляет их к backend. Cookie устанавливает сервер.

На экране входа доступны два демонстрационных профиля из контракта. После входа нажмите «Новая заявка». Это создаёт пустой черновик на сервере. Заполните необходимые для проверки поля и дождитесь «Изменения сохранены». Неполные сведения допустимы: окончательная достаточность и условия кредитования пока не проверяются.

## Шаги оформления

1. **Продукт:** три направления с демонстрационными ставками и диапазонами из каталога; необязательный помощник.
2. **Параметры:** сумма и месяцы обычного кредита с ползунками/ручным вводом и расчётом; для овердрафта сумма, дни и ожидаемое поступление. Под расчётами — цель. До выбора продукта можно сохранить неполные сумму и цель; неприменимые поля не показываются.
3. **Проверка:** обычная сводка и актуальный расчёт, ссылки «Изменить». Пустые значения обозначены; отправка пока не реализована.


Изменения сохраняются через 1500 мс после паузы. «Назад», «Продолжить» и навигация по шагам запускают сохранение сразу, не блокируя заполнение. Передаются только изменённые корректные поля; неверный промежуточный ввод не очищает серверное значение. При смене продукта его код и зависимые параметры обновляются вместе. Ответы сохранения не заменяют текущий текст и не сбрасывают шаг; форматирование и копейки ручного ввода сохраняются на экране.

Индикатор показывает ожидание, сохранение, подтверждённый успех, неполные/неверные поля или ошибку. Один запрос сохранения выполняется за раз; накопленный новый ввод отправляется с полученной версией. При сетевой ошибке есть «Повторить сохранение». 401 требует повторного входа, 409 — явной загрузки серверной версии с предупреждением; автоматической перезаписи конфликта нет. Чужая компания не может получить прежнюю заявку через запоздавший ответ.

На третьем шаге «Сохранить и выйти» дожидается очереди и возвращает к списку. При невалидном поле остаётся форма и открывается его шаг. Обычный выход к списку/смена профиля также ждут сохранения; при неудаче можно остаться и повторить либо подтвердить выход без остатка изменений. Только явный выход/вход/загрузка временно блокируют форму; фоновое сохранение — нет.

После обновления страницы открывается первый шаг с подтверждёнными сервером данными. Для несохранённого остатка действует предупреждение об уходе. Автосохранение требует связи; офлайн-хранилища и гарантии сохранения при принудительном закрытии нет.

Порядок и принадлежность полей описаны в `src/draft-steps.ts`; содержимое шагов — в `src/components/draft/`. Это позволяет позже добавить согласованный раздел с финансовыми сведениями. Для новых хранимых данных потребуются согласованные изменения типов, API и БД: текущий интерфейс их не придумывает. Полного профиля с ИНН и банковского кабинета пока нет.

## Проверки и сборка

```bash
npm test
npm run build
```

`npm test` проверяет обработку ввода, HTTP-клиент и действия пользователя через реальные React-компоненты. Ответы внешнего backend в этих тестах моделируются на границе fetch по полному контракту. Тестовые вспомогательные файлы не используются рабочим приложением.

`npm run build` проверяет TypeScript и создаёт `dist/`. Vite dev proxy применяется только при разработке. Для развёрнутой сборки требуется отдельное перенаправление `/api` на backend тем же сервером; `npm run preview` сам этого не обеспечивает. Docker-сборка frontend и промышленный способ входа не входят в этот первый шаг.

## Что проверить вместе с backend Виктора

- Войти, создать черновик, сохранить его и обновить страницу: значения остаются, выбранная заявка открывается по `#draft/id`.
- Перезапустить backend с той же PostgreSQL: заявка и вход сохраняются.
- Войти второй компанией: список и прямой доступ к чужой заявке изолированы сервером.
- Дважды создать с одним Idempotency-Key: одна заявка.
- Открыть в двух окнах, сохранить разные изменения: второе сохранение получает 409 и не перезаписывает первое без явного действия.
- Остановить backend во время редактирования: ввод остаётся и ложного успеха нет.
- Сменить продукт: неприменимые сроки и ожидаемые поступления очищаются.
- Сменить профиль в соседней вкладке, затем создать или сохранить в старой: старый кабинет очищается и просит войти заново. Ответ с другой компанией также не должен попасть в старый кабинет.

Успешные frontend-тесты не доказывают хранение в настоящей БД и защиту backend. Общая интеграция считается выполненной только после совместной проверки выше.

## Что пока отсутствует

Отправка на рассмотрение, кабинет сотрудника, банковское решение, расчёт овердрафта, подключение настоящего ассистента, подписание и выдача — следующие шаги проекта. В интерфейсе черновик не выдаётся за отправленную заявку.

## Открытие и удаление из списка

Вся карточка заявки — доступная с клавиатуры кнопка открытия. Отдельная кнопка корзины есть только у DRAFT; она не открывает заявку. Подтверждение — окно внутри сайта с номером/целью черновика и предупреждением об отсутствии восстановления, без window.confirm. Первоначальный фокус на «Отмена»; Escape отменяет до начала удаления. Пока запрос выполняется, кнопки заблокированы, окно не закрывается по Escape; при ошибке сообщение и возможность повторить остаются внутри окна. Корзина не смещается при нажатии. После 204 DELETE карточка исчезает и счётчик уменьшается, при ошибке карточка остаётся; можно повторить действие. При 404/409 доступно обновление списка. Перед удалением перепроверяется компания текущей сессии; статус, владельца и версию окончательно проверяет backend. Удаление доступно только из списка, поэтому не конкурирует с автосохранением открытой формы в этой вкладке; другая вкладка защищена серверной версией.
