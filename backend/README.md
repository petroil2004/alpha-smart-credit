# Backend

FastAPI + SQLAlchemy + PostgreSQL. Актуальные возможности, запуск всего приложения и сценарий проверки: [корневой README](../README.md). Полное API — `/docs` и `/openapi.json`; [объяснение правил и имитаций](../docs/jury/api-and-policy.md).

Реализованы две роли, шесть синтетических компаний, три продукта, сохранение черновиков, отправка со снимком данных, уточнения и документы, проверенные ручные поправки, объяснимая оценка, решение и условная выдача. ФНС/БКИ локально смоделированы. Внешние реальные банковские системы, OCR, подпись и реальные деньги не используются.

## Локальная разработка

Нужны Python 3.12 и PostgreSQL 16; зависимости в `requirements-dev.txt`. Установка в отдельное виртуальное окружение:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
```

Из каталога backend задать DATABASE_URL к своей локальной БД и запустить `.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000`. На Windows путь к исполняемым файлам окружения `.venv\Scripts\`. Сначала проверить уже работающие процессы и Docker; не поднимать второй сервер на том же порту. Для обычной проверки предпочтительнее Docker Compose.

Синтетические профили добавляются при старте без очистки существующих данных. Схема создаётся/дополняется совместимыми шагами, полноценного инструмента промышленных миграций пока нет.

## Проверки на отдельной базе

Тесты удаляют и создают таблицы, поэтому DATABASE_URL обязательно должен указывать на отдельную БД с именем, заканчивающимся `_tests`. **Никогда не запускайте их на рабочей БД.**

Для нового Compose-проекта с настройками `.env.example` подготовить такую базу один раз (если она уже существует, повторять создание не нужно):

```bash
docker compose exec db createdb -U credit credit_cabinet_tests
```

Целевой прогон в одноразовом контейнере, подключённом к уже существующей БД:

```bash
docker compose run --rm --no-deps -e DATABASE_URL=postgresql+psycopg://credit:credit@db:5432/credit_cabinet_tests backend pytest -q tests/test_external_checks.py tests/test_review.py tests/test_assistant.py tests/test_staff_workspace.py tests/test_disbursements.py tests/test_submissions.py
```

При других POSTGRES_USER/POSTGRES_PASSWORD подставить свои локальные значения. Для работающего проекта использовать прежнее имя через `-p`. Эти команды не требуют удаления volume или остановки рабочей базы. Полный набор при необходимости — `pytest -q`; тесты LLM используют локальный HTTP-имитатор, не платный API.

Изменённые файлы должны попасть в образ перед прогоном: `docker compose build backend`. Иначе тестируется прежний образ. Реальное подключение модели проверяется отдельно по [инструкции](../docs/technical/assistant-integration.md).
