# Умный кредитный кабинет предпринимателя

Единый веб-продукт для действующего клиента малого бизнеса и кредитного сотрудника, разработанный в рамках хакатона от Альфа-Банка.

Все компании, финансы, кредитные истории и операции синтетические. Реальные банковские системы не вызываются.

## Что реализовано

Три продукта: оборотный кредит, кредит на оборудование и овердрафт.

Кредитный путь: выбор продукта → параметры и цель → отправка → рассмотрение → при необходимости уточнение в чате → решение сотрудника → согласие клиента → демонстрационная выдача или открытие лимита. После выдачи сценарий заканчивается; при отказе клиент видит причину.

- **Кабинет клиента:** автосохранение, список заявок, статусы, история и уведомления.
- **Рабочее место сотрудника:** очередь с фильтрами, проверки, скоринг и решение с отдельным подтверждением.
- **Уточнения:** общий чат и PDF/PNG/JPG до 5 МБ по запросу сотрудника. Проверенные поправки обновляют профиль компании; первоначальные данные отправленной заявки сохраняются для истории.
- **Финансовый пульс:** график поступлений и расходов за шесть месяцев, показатели и цветная оценка. При нехватке данных показана причина.
- **Расчёты и проверки:** объяснимый балльный скоринг, допустимый платёж/лимит, локальные имитации ФНС и БКИ. Пороги демонстрационные, не правила Альфа-Банка. Права и повторные операции контролирует сервер.
- **Необязательный помощник:** подбор продукта и объяснение понятий на основе серверного каталога. Модель не принимает решения; весь кредитный путь доступен без неё.

## Запуск для проверки

Нужны **Git и запущенный Docker Desktop** с Docker Compose. На Windows — Linux-контейнеры и WSL 2. Ориентир для приложения без ИИ: компьютер с 8–12 ГБ ОЗУ и несколькими свободными гигабайтами диска. При первом запуске нужен интернет. Python, Node.js и PostgreSQL отдельно устанавливать не требуется.

Примите приглашение в приватный репозиторий. При клонировании Git может предложить вход через браузер — используйте приглашённый GitHub-аккаунт.

**Скачайте проект:**

```bash
git clone https://github.com/petroil2004/alpha-smart-credit.git
cd alpha-smart-credit
```

**В свежей копии создайте `.env`:**

macOS/Linux:

```bash
cp .env.example .env
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Существующий `.env` не перезаписывайте. По умолчанию ИИ выключен.

**Запустите приложение:**

```bash
docker compose up -d --build --wait
```

Откройте [кабинет](http://127.0.0.1:8080). Дополнительно доступны [Swagger](http://127.0.0.1:8000/docs), [OpenAPI](http://127.0.0.1:8000/openapi.json) и [проверка состояния](http://127.0.0.1:8000/health).

Если приложение уже развёрнуто, используйте его папку и прежнее имя проекта (`docker compose ls`, при необходимости `-p`), чтобы не создавать вторую базу. Порты 8080 и 8000 должны быть свободны; порт кабинета меняется переменной `FRONTEND_PORT`.

Остановка: `docker compose stop`. Повторный запуск: `docker compose up -d --wait`. Заявки и документы сохраняются в PostgreSQL. **Не выполняйте `docker compose down -v`: эта команда удаляет базу.**

<details>
<summary>Если запуск не удался</summary>

- **WSL не установлен:** в PowerShell от имени администратора выполните `wsl --install --no-distribution`, перезагрузите компьютер, выполните `wsl --update` и откройте Docker Desktop. Отдельная Ubuntu не нужна.
- **Ошибка подключения к Docker API / npipe:** дождитесь `Engine running` в Docker Desktop. Команда `docker info` должна показывать раздел Server без ошибки.
- **TLS handshake timeout при загрузке PostgreSQL:** повторите `docker pull postgres:16-alpine`, затем запуск. При повторении проверьте другую сеть или настройки прокси/VPN; данные удалять и TLS отключать не требуется.
- **Сервис не запустился:** выполните `docker compose ps -a` и `docker compose logs --tail=100 backend frontend db`. При обращении за помощью не публикуйте содержимое `.env` и API-ключи.

</details>

## Как проверить за 5–10 минут

1. Войти как клиент «ООО Демо Торг» (`demo-client-1`). Создать оборотный кредит 300 000 ₽ на 36 месяцев, указать цель и отправить.
2. Выйти и войти сотрудником (`demo-staff-1`). Открыть заявку, развернуть «Проверка и скоринг»: источники, балл, причины, допустимый платёж.
3. Запросить пояснение и отметить «Нужен документ». Войти клиентом, отправить ответ и синтетический PDF/PNG/JPG.
4. Войти сотрудником, проверить ответ. При необходимости нажать «Скорректировать данные», указать изменённые значения и основание. Завершить уточнение, нажать «Одобрить», проверить сводку в окне и подтвердить одобрение. «Отмена» не сохраняет решение.
5. Войти клиентом, открыть уведомление, проверить условия, дать согласие и получить экран демонстрационной выдачи. Повторное нажатие не выдаёт деньги дважды.
6. Для отказа создать отдельную заявку «Демо Торг» 6 000 000 ₽ на 12 месяцев: балл может быть высоким, но платёж превышает допустимый. Сотрудник отказывает с причиной.

Полный набор сценариев и таблица шести аккаунтов: [проверка жюри](docs/jury/scenarios.md). Демо-вход без пароля — принятое упрощение для синтетического стенда, не промышленная авторизация.

## Необязательный ИИ

Рекомендуемый вариант: Ollama на компьютере проверяющего, модель `qwen3:4b-instruct-2507-q4_K_M`. Приложение остаётся в Docker. GPU не обязателен; на CPU первый ответ может быть медленным. Можно указать собственного OpenAI-совместимого провайдера с моделью с открытыми весами. Платный сервис и компьютер автора не нужны.
