# Умный кредитный кабинет предпринимателя

Командный проект хакатона Альфа-Банка: прототип кредитного процесса для малого бизнеса, связывающий кабинет предпринимателя и работу банковского сотрудника.

## Текущее состояние

В репозитории есть задания команды, клиентский интерфейс в `frontend/`, FastAPI backend в `backend/` и PostgreSQL через Docker Compose. Работает демонстрационный вход и черновик: потребность → продукт → параметры → проверка, сохранение и повторное открытие. Полный кредитный кабинет ещё не реализован.

Для оборотного кредита и оборудования добавлен серверный калькулятор: сумма и срок задаются ползунками или вручную, показываются ставка, платёж, общая сумма выплат и переплата. Условия загружаются из каталога backend. Запрос расчёта не изменяет заявку; ввод независимо сохраняется автоматически. Расчёт не означает одобрения; калькулятор овердрафта, оценка бизнеса и отправка пока не реализованы. [Контракт калькулятора](docs/technical/loan-calculator-contract.md).

На шаге «Потребность» доступны карточки типовых целей и «Другое» со свободным описанием. На втором шаге «Продукт» под вариантами финансирования находится раскрывающаяся заготовка помощника: модель ещё не подключена, ввод и отправка сообщений отключены. Раскрытие сохраняется при возврате на этот шаг. Изменения сохраняются прежним API через 1,5 секунды после паузы и при переходах; выбор карточки не меняет продукт автоматически.

Согласованы три продукта: оборотный кредит, кредит на оборудование и упрощённый овердрафт. В прототипе будут кабинет клиента и рабочее место сотрудника, объяснимая балльная оценка риска, принятие предложения, моделирование подписания и предоставления финансирования. Ассистент планируется только на втором шаге «Продукт» до отправки заявки (`DRAFT`): использует цель и сумму с первого шага, помогает сравнить продукты и понять условия; объясняет серверный расчёт, если он уже есть. При возврате на второй шаг введённые данные и разговор сохраняются. Заготовка уже перенесена на второй шаг; настоящий разговор с моделью ещё предстоит подключить. После отправки статусы и решения объясняет интерфейс, вопросы по открытому запросу уточнения клиент задаёт сотруднику в той же заявке; документы загружаются на странице заявки. Это целевое поведение, ещё не реализованное целиком. Ассистент подключается через локальную Ollama; первый кандидат модели — `qwen3:4b-instruct-2507-q4_K_M`. Модель пока не установлена и не проверена в рамках проекта.

## Локальный запуск

Сначала запустите Docker Desktop. Создайте локальный `.env` по образцу `.env.example`, если его ещё нет. Из корня репозитория:

```bash
docker compose up --build -d
```

Backend доступен на `http://127.0.0.1:8000`. Подробности — в [backend/README.md](backend/README.md). Не запускайте тесты backend на БД с сохранёнными черновиками: инструкция описывает отдельную тестовую базу.

С установленным Node.js 22.12+ поддерживаемой ветки:

```bash
cd frontend
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173`. Для реальной работы нужен backend по согласованному контракту на `127.0.0.1:8000`. Без него интерфейс сообщает о недоступности сервиса. Подробности настроек, тестов и ограничений — в [frontend/README.md](frontend/README.md). Ассистент для этого первого шага не требуется.

Если порт 5173 занят, запустите `npm run dev -- --port 5180` из `frontend/` и откройте `http://127.0.0.1:5180`.

## Работа с репозиторием

Используем короткую отдельную ветку `codex/имя-задача` от актуальной `main`. Изменения сохраняются осмысленными коммитами и предлагаются через PR. После проверки другим участником Петя или Витя объединяет их обычным merge. Подробности и команды — в Git-инструкции выше.

Для работы на своём компьютере получите репозиторий командой `git clone https://github.com/petroil2004/alpha-smart-credit.git` и откройте полученную папку. Не запускайте clone поверх уже существующей рабочей копии. Витя работает в собственной копии; у Пети рабочая папка этого чата уже связана с репозиторием через `origin`.

Для будущих задач Codex прочитает [AGENTS.md](AGENTS.md), содержащий общие правила проекта. Материалы от коллег сначала проверяются, затем включаются в общую версию; чат не заменяет актуальные файлы репозитория.

Все демонстрационные компании, финансовые сведения и операции будут синтетическими. Реальные банковские операции не выполняются.

Автосохранение показывает подтверждённое состояние, сохраняет корректные поля отдельно от временно невалидных и останавливается при конфликте версий или истечении входа. На последнем шаге «Сохранить и выйти» дожидается сохранения и возвращает к списку; отправка в банк пока не реализована. [Дизайн автосохранения](docs/superpowers/specs/2026-10-23-autosave-design.md).

В «Моих заявках» открывается вся карточка, включая работу с клавиатуры. Только у DRAFT есть отдельная кнопка «Удалить черновик» с подтверждением: после ответа сервера запись удаляется из списка и базы, счётчик обновляется. Сервер проверяет компанию, статус и актуальную версию; отправленные заявки не удаляются. При ошибке карточка остаётся, при устаревшем списке доступно обновление. Ключ создания остаётся квитанцией, поэтому повтор старого запроса не восстанавливает удалённый черновик.
