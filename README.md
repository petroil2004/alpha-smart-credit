# Умный кредитный кабинет предпринимателя

Командный проект хакатона Альфа-Банка: прототип кредитного процесса для малого бизнеса, связывающий кабинет предпринимателя и работу банковского сотрудника.

## Текущее состояние

Работает демонстрационный кредитный путь для трёх продуктов: черновик → отправка → уточнения → скоринг → решение сотрудника → согласие клиента → демонстрационное получение финансирования. Это прототип с синтетическими данными, без юридической подписи и реального перевода денег. Помощник по выбору подключается через настраиваемый OpenAI-совместимый API; без модели основной путь работает.

Для оборотного кредита и оборудования сервер рассчитывает ставку, платёж, общую сумму выплат и переплату. Для овердрафта клиент указывает лимит, срок использования, планируемую оплату и ожидаемое поступление; сервер проверяет покрытие и рассчитывает проценты при отправке. Условия загружаются из каталога backend, ввод сохраняется автоматически. Расчёт не означает одобрения.

Маршрут оформления состоит из трёх шагов: «Выберите продукт» → «Настройте условия» → «Проверьте заявку». На первом шаге под продуктами раскрывается помощник: проверяется доступность модели, доступны диалог и рекомендация с явной кнопкой выбора. Без модели ручное оформление работает. На параметрах сумма и срок связаны с калькулятором; под расчётами находится текстовое поле «На что нужны средства» до 500 символов. Готовых карточек целей нет. Изменения сохраняются прежним API через 1,5 секунды после паузы и при переходах. Старые сохранённые цели открываются как обычный текст.

Сотрудник открывает собственный демонстрационный профиль по имени в шапке (ФИО, должность, отдел и город). В карточке один сворачиваемый блок «Проверка и скоринг» с пересчётом внутри; решение показывается отдельно. Незавершённый черновик сохраняется автоматически, выход — через «Все заявки» или логотип; отдельной кнопки «Сохранить и выйти» нет.

Уточнение — единый чат по запросу сотрудника. Текст ответа автосохраняется как личный черновик, загруженные файлы также скрыты от сотрудника до «Отправить ответ». После отправки обе стороны могут продолжать переписку; запрос закрывает сотрудник кнопкой «Завершить уточнение», затем заявка возвращается на рассмотрение. Принимаются PDF, PNG и JPG до 5 МБ, не более пяти файлов. Прикрепление доступно только в запросе с отметкой «Нужен документ»; сервер также проверяет это условие. Распознавание не реализовано.

После отправленного ответа сотруднику доступна кнопка «Скорректировать данные» с выбором финансов или профиля компании. Финансовая таблица содержит шесть месяцев даже при отсутствии исходных значений; профиль позволяет исправить форму, ИНН, ОКВЭД, регистрацию и признак клиента банка. Сохраняются только изменённые проверенные значения с основанием, автором и временем; скоринг пересчитывается. Исходные сведения заявки сохраняются. Клиент не вводит отдельную финансовую анкету; текст и документы сами по себе не меняют скоринг. Запросить можно любые пояснения и документы, подтверждённые поправки финансов и профиля учитываются в карточке этой заявки и её скоринге; исходный общий демо-профиль не перезаписывается. [Контракт единого чата](docs/technical/clarification-chat.md).

В заявке на оборудование собирается только сумма кредита, отдельное поле стоимости покупки убрано. Продукт отличается целевой покупкой оборудования, диапазоном 500 тыс.–10 млн ₽ и сроком 12–60 месяцев; у оборотного — 300 тыс.–6 млн ₽ и 12–36 месяцев. Ставки и расчёт в этой версии одинаковы.

У заявок постоянные сквозные числовые номера, UUID остаётся внутренним адресом API. При обновлении существующей БД номера присваиваются без удаления заявок. Даты использования средств и поступления для погашения должны быть не раньше текущей даты Москвы: проверка при вводе, сохранении и отправке. Исторические даты отправленных заявок не переписываются.

По ссылке «Полные условия финансирования» открывается отдельная страница документов для трёх продуктов. Полный текст пока не опубликован; страница явно обозначена как образец. Демонстрационное согласие клиента не заменяет договор.

Следующий шаг оформления доступен после заполнения обязательных полей предыдущего; незавершённый черновик сохраняется автоматически и при выходе. В помощнике Enter отправляет сообщение, Shift+Enter добавляет строку. Выбор рекомендации отмечает продукт и возвращает к карточкам.

У клиента есть колокольчик с уведомлениями об изменениях статуса: непрочитанные отмечены красной точкой, нажатие открывает заявку. Отметки о прочтении сохраняются в PostgreSQL для текущего аккаунта. Обновление — раз в 30 секунд, при возвращении к окну и при открытии списка уведомлений. У сотрудника очередь разделена на текущие и завершённые заявки с фильтром статуса. История, проверка и скоринг свёрнуты по умолчанию; путь заявки отображается при рассмотрении, уточнениях, одобрении и демонстрационном получении; при отказе скрыт.

Работают три продукта: оборотный кредит, оборудование и упрощённый овердрафт; шесть синтетических компаний; роли клиента/сотрудника; финансовые уточнения, документы, объяснимая балльная оценка и решение с причиной. Профиль компании вынесен на отдельную страницу. После одобрения клиент подтверждает параметры: сервер один раз фиксирует демонстрационное зачисление (для овердрафта — открытие лимита), затем показывает экран успеха. Юридическая подпись и реальная выдача денег не выполняются. Помощник доступен только до отправки на шаге продукта; получает диалог и выбранный продукт, не получает автоматически финансовые данные или скоринг. Модель распознаёт задачу, проверенные условия ответа берутся из каталога. Основной кандидат — уже установленная у Пети `qwen3:4b-instruct-2507-q4_K_M` на Windows-ПК с RTX3060; подключение проверено на пяти целевых вопросах, модель полностью размещается на GPU. Настраиваются base URL, ключ и модель для собственного провайдера жюри. После отправки вопросы по уточнению клиент задаёт сотруднику внутри заявки.

Утверждённое оформление и новый маршрут: [три шага от 23.10.2026](docs/superpowers/specs/2026-10-23-three-step-redesign.md). Главная — тёмный приветственный блок и светлый список заявок, продукты — пастельные карточки, параметры — калькулятор и цель, проверка — простая сводка. Отдельная обязательная категория цели исключена из MVP; применимость описания к продукту уточняет сотрудник.

Все три продукта можно отправить после подтверждения сведений на третьем шаге. Сервер фиксирует снимок заявки, профиля, финансов и расчёта, регистрирует её на рассмотрение; повтор запроса не дублирует отправку. Вход «Сотрудник банка» (`demo-staff-1`) открывает очередь и карточку со снимком/историей. Сотрудник может запросить текст, документ и структурированные финансовые значения. Только явно принятые сотрудником структурированные значения участвуют в новом расчёте; текст и файл сами числа не меняют. Сервер показывает воспроизводимый демонстрационный балл, причины, недостающие сведения и позволяет сотруднику одобрить или отклонить заявку с понятной причиной. [Итог этапа](docs/technical/2026-10-24-mvp-completion.md).

Сотрудник может запросить сведения и документ в отправленной заявке: `UNDER_REVIEW → NEEDS_INFO`. Клиент сохраняет текст ответа, прикрепляет синтетические PDF/TXT до 5 МиБ и ведёт переписку в том же запросе. Только явная отправка ответа возвращает заявку на рассмотрение; исходный снимок и расчёт не меняются. Документы хранятся в PostgreSQL, доступны своей компании и сотруднику. Сведения клиента помечены как непроверенные. [Контракт уточнений](docs/technical/clarifications-contract.md), [фактические проверки](docs/technical/2026-10-24-clarifications-verification.md).

Демо-профили загружаются один раз из фиксированных наборов в PostgreSQL без перезаписи прежних данных. Профиль и финансы доступны клиенту на отдельной странице компании; сотрудник видит историческую копию в отправленной заявке. Пропуск не равен нулю; среднее показывается только для полного ряда. ИНН, ОКВЭД и статус регистрации берутся из той же локальной базы как явная имитация ФНС — внешних запросов нет. Скоринг также демонстрационный, не является банковской моделью и не принимает решение без сотрудника.

## Локальный запуск

Перед запуском проверьте существующие серверы, `docker ps` и `docker compose ls`. Используйте уже работающий compose-проект и его имя (`-p`), чтобы не создать второй backend/БД. Не удаляйте volume с черновиками. Если сервисов нет, сначала запустите Docker Desktop. Создайте локальный `.env` по образцу `.env.example`, если его ещё нет. Из корня репозитория:

```bash
docker compose up --build -d
```

Кабинет доступен на `http://127.0.0.1:8080`, backend — на `http://127.0.0.1:8000`. Все три компонента приложения запускаются в Docker. Для ИИ укажите в локальном `.env` `ASSISTANT_ENABLED=true`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Порядок запуска Ollama на Windows-ПК, CPU-вариант и проверка со своим провайдером описаны в [инструкции помощника](docs/technical/assistant-integration.md). Подробности — в [backend/README.md](backend/README.md). Не запускайте тесты backend на БД с сохранёнными черновиками: инструкция описывает отдельную тестовую базу.

Для проверки ИИ без компьютера автора используйте локальный CPU-профиль Docker. В `.env` включите `ASSISTANT_ENABLED=true`, оставьте `LLM_BASE_URL=http://ollama:11434/v1`, пустой ключ, модель из примера и `LLM_TIMEOUT_SECONDS=180`. Затем:

```bash
docker compose --profile assistant up -d --build --wait
docker compose --profile assistant exec ollama ollama pull qwen3:4b-instruct-2507-q4_K_M
```

Первое скачивание образа Ollama и модели — около 5,3 ГБ на arm64. Желательно выделить Docker 4 CPU и 6 ГиБ памяти; CPU отвечает заметно медленнее GPU. Войти клиентом → новая заявка → «Помочь с выбором» → «Хочу купить печь для пекарни». Продукт выбирается только явной кнопкой после рекомендации. [Полные шаги, повторный запуск и проверочные вопросы](docs/technical/assistant-integration.md#проверка-жюри-на-cpu-без-windows-пк-и-платного-api), [результаты реального CPU-запуска](docs/technical/2026-10-25-jury-cpu-verification.md). Основной кредитный путь доступен без модели и платного API.

Для отдельного режима разработки frontend (не требуется для Docker-запуска), с установленным Node.js 22.12+ поддерживаемой ветки:

```bash
cd frontend
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173`. Для реальной работы нужен backend по согласованному контракту на `127.0.0.1:8000`. Без него интерфейс сообщает о недоступности сервиса. Подробности настроек, тестов и ограничений — в [frontend/README.md](frontend/README.md). Ассистент для этого первого шага не требуется.

Если порт 5173 занят, сначала проверьте, не работает ли уже frontend этого проекта, и используйте его. Другой порт выбирайте только для отдельного осознанного запуска.

## Работа с репозиторием

Используем короткую отдельную ветку `codex/имя-задача` от актуальной `main`. Изменения сохраняются осмысленными коммитами и предлагаются через PR. После проверки другим участником Петя или Витя объединяет их обычным merge. Подробности и команды — в Git-инструкции выше.

Для работы на своём компьютере получите репозиторий командой `git clone https://github.com/petroil2004/alpha-smart-credit.git` и откройте полученную папку. Не запускайте clone поверх уже существующей рабочей копии. Витя работает в собственной копии; у Пети рабочая папка этого чата уже связана с репозиторием через `origin`.

Для будущих задач Codex прочитает [AGENTS.md](AGENTS.md), содержащий общие правила проекта. Материалы от коллег сначала проверяются, затем включаются в общую версию; чат не заменяет актуальные файлы репозитория.

Все демонстрационные компании, финансовые сведения и операции будут синтетическими. Реальные банковские операции не выполняются.

Автосохранение показывает подтверждённое состояние, сохраняет корректные поля отдельно от временно невалидных и останавливается при конфликте версий или истечении входа. На последнем шаге «Сохранить и выйти» дожидается сохранения и возвращает к списку, сохраняя неполный черновик. Для оборотного кредита есть отдельная отправка на рассмотрение. [Дизайн автосохранения](docs/superpowers/specs/2026-10-23-autosave-design.md).

В «Моих заявках» открывается вся карточка, включая работу с клавиатуры. Только у DRAFT есть отдельная кнопка «Удалить черновик» с подтверждением: после ответа сервера запись удаляется из списка и базы, счётчик обновляется. Сервер проверяет компанию, статус и актуальную версию; отправленные заявки не удаляются. При ошибке карточка остаётся, при устаревшем списке доступно обновление. Ключ создания остаётся квитанцией, поэтому повтор старого запроса не восстанавливает удалённый черновик.
