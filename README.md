# Умный кредитный кабинет предпринимателя

Прототип хакатона Альфа-Банка: единый веб-продукт для действующего клиента малого бизнеса и кредитного сотрудника. Все компании, финансы, кредитные истории и операции синтетические. Реальные банковские системы не вызываются.

## Что работает

Три продукта: оборотный кредит, оборудование и овердрафт. Путь: выбор продукта → параметры и цель → проверка и отправка → рассмотрение → при необходимости уточнение в чате → решение сотрудника → согласие клиента → демонстрационное получение кредита или открытие лимита. Отказ содержит причину. После выдачи сценарий заканчивается.

Есть автосохранение, отдельные профили компании и сотрудника, очередь с фильтрами, числовые номера, история, уведомления и проверка прав на сервере. В момент отправки фиксируются версии заявки, каталога и сведений компании. Повтор критичного запроса не создаёт повторную операцию.

Документы передаются по запросу сотрудника: PDF/PNG/JPG до 5 МБ, не больше пяти файлов. Черновики текста и файлов не видны сотруднику до явной отправки. После ответа сотрудник может исправить финансовые и регистрационные сведения с основанием; исходный снимок сохраняется. Запрос закрывает сотрудник. Распознавания документов нет.

Балльный скоринг использует четыре объяснимых фактора. Отдельные правила учитывают допустимый платёж/лимит и результаты имитаций ФНС и БКИ. Сбой источника не становится отказом; просрочки требуют ручной оценки с причиной. Веса и пороги временные демонстрационные, не реальные правила Альфа-Банка.

Необязательный помощник подбирает продукт и объясняет понятия. Модель только определяет намерение и тему; ответы, объяснения и ставки формирует сервер из каталога и справочника. Модель не одобряет кредит и не выполняет действия. Без неё весь кредитный путь работает.

## Запуск для проверки

Нужны Git и Docker Engine/Desktop с Compose v2. Для приложения без ИИ ориентир — обычный компьютер с 8–12 ГБ ОЗУ и несколькими свободными гигабайтами диска; это не измеренный предел нагрузки. При первом запуске нужен интернет для образов и зависимостей. На Mac/Windows Docker Desktop должен быть запущен.

```bash
git clone https://github.com/petroil2004/alpha-smart-credit.git
cd alpha-smart-credit
```

Создайте `.env` из `.env.example`: macOS/Linux — `cp .env.example .env`, Windows PowerShell — `Copy-Item .env.example .env`. Существующий `.env` не перезаписывайте. По умолчанию ИИ выключен.

```bash
docker compose up -d --build --wait
```

- Кабинет: http://127.0.0.1:8080
- Swagger: http://127.0.0.1:8000/docs
- OpenAPI: http://127.0.0.1:8000/openapi.json
- Проверка состояния: http://127.0.0.1:8000/health

Если приложение уже запущено, сначала проверьте `docker compose ls` и используйте то же имя проекта через `-p`. Не создавайте вторую БД. Порты 8080 и 8000 должны быть свободны; порт интерфейса меняется через `FRONTEND_PORT`. Для остановки — `docker compose stop`, повторного запуска — `docker compose up -d --wait`. Заявки сохраняются в volume PostgreSQL. **Не выполняйте `down -v`: это удаляет базу.**

## Как проверить за 5–10 минут

1. Войти как клиент «ООО Демо Торг» (`demo-client-1`). Создать оборотный кредит 300 000 ₽ на 36 месяцев, указать цель и отправить.
2. Выйти и войти сотрудником (`demo-staff-1`). Открыть заявку, развернуть «Проверка и скоринг»: источники, балл, причины, допустимый платёж.
3. Запросить пояснение и отметить «Нужен документ». Войти клиентом, отправить ответ и синтетический PDF/PNG/JPG. До отправки сотрудник не видит черновик.
4. Войти сотрудником, проверить ответ. При необходимости нажать «Скорректировать данные», указать изменённые значения и основание. Завершить уточнение, одобрить.
5. Войти клиентом, открыть уведомление, проверить условия, дать согласие и получить экран демонстрационной выдачи. Повторное нажатие не выдаёт деньги дважды.
6. Для отказа создать отдельную заявку «Демо Торг» 6 000 000 ₽ на 12 месяцев: балл может быть высоким, но платёж превышает допустимый. Сотрудник отказывает с причиной.

Полный набор сценариев и таблица шести аккаунтов: [проверка жюри](docs/jury/scenarios.md). Демо-вход без пароля — принятое упрощение для синтетического стенда, не промышленная авторизация.

## Необязательный ИИ

Рекомендуемый вариант: Ollama на компьютере проверяющего, модель `qwen3:4b-instruct-2507-q4_K_M`. Приложение остаётся в Docker. GPU не обязателен; на CPU первый ответ может быть медленным. Можно указать собственного OpenAI-совместимого провайдера с моделью с открытыми весами. Платный сервис и компьютер автора не нужны.
